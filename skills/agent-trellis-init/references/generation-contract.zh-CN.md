# 生成契约

## 选择并实例化模板

英文输出使用 `assets/en/seed/`，中文输出使用 `assets/zh-CN/seed/`。保留相对路径并移除 `.tmpl` 后缀。对于 `conditional/` 下有证据支持的文件，还要移除开头的 `conditional/` 路径段。替换每个双花括号模板字段；目标仓库中不得出现未解析占位符。

根据目标仓库已经建立的文档语言，只生成一种语言。除非目标仓库已经维护双语政策，否则不要把分发仓库的双语配对政策安装进去。

## 核心生命周期

默认方案包括：

- 根 `AGENTS.md`，拥有边界、事实归属、工作流和安全路由；
- `docs/AGENTS.md`，拥有文档规则；
- `docs/architecture.md`，拥有当前组件与接口关系；
- `docs/development.md`，拥有环境和 canonical 开发命令；
- `docs/testing.md`，拥有验证入口状态和结果解释；
- `.agents/notes/`，用于长期决策，包含契约、局部指令和一份采用决策 Note；
- `.agents/work/`，用于跨会话临时执行状态，包含局部指令；以及
- 所选模板树提供的六个项目 Skills。

除非初始化本身会跨会话或需要明确交接，否则不要创建 Active Work Item。

## 条件 owner

当证据表明存在高影响外部操作，且其授权与安全边界需要长期 owner 时，创建 `docs/safety.md`。当多个组件依赖共享 schema、协议、身份、顺序、单位、坐标或时间约定，而且尚无适当 owner 时，创建 `docs/contracts.md`。

信息安全、隐私、部署、迁移、合规和其他专项文档遵循相同规则：只为已建立的需求添加，并定义其确切归属。不得将推测性检查清单复制到当前状态文档中。

## 合并政策

- 在理解已有内容的意图和 owner 前，保留所有已有内容。
- 已经存在适当 owner 时，添加链接而非创建竞争文档。
- 在适用范围最窄的 `AGENTS.md` 中合并规则。
- 当前事实放在 owning 文档，长期理由放在 Agent Notes，临时执行状态放在 Active Work Items。
- 当正确性依赖某未知项时明确记录；省略没有操作影响的琐碎信息。
- 初始化期间绝不修改源码、产品配置或无关文档。

采用决策 Note 记录被接受的治理边界和取舍。它不得叙述编辑过程，也不得宣称未实际完成的验证。
