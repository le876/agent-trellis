# 验证契约

## 结构检查

写入后验证：

- 每个本地链接文件和标题都存在；
- 每项长期事实都有一个明确 owner；
- architecture 只描述有证据支持的组件与接口关系；
- testing 拥有验证入口状态和结果解释；
- safety 存在时，拥有授权和安全判断，而不是命令说明；
- development 拥有 canonical 命令和环境设置；
- Note 与 Work 契约定义创建、更新、完成和归档行为；
- 每个已安装 Skill 都有只包含 `name` 与 `description` 的有效 frontmatter；以及
- 不存在未解析的双花括号模板字段。

当目标仓库已有验证器安全、可用且相关时，使用这些验证器。不要仅为了验证初始化而添加依赖。

## 行为检查

从最终 diff 确认已有指令和用户修改均被保留。检查条件 owner 是否引用了仓库证据，并确认未知事实仍保持未知。再次进行只读审计时，不得提出重复文件或重复事实归属。

只有实际运行并观察到结果的检查才能报告为通过。不可用或不安全的检查应记录为未运行，并说明原因。

## 交接

报告：

1. 创建、合并和保留的文件；
2. owner map 变更；
3. 条件 owner 及其证据；
4. 实际运行的检查与结果；
5. 未解决的未知项或冲突；以及
6. 重复审计是否幂等。

保持目标工作树未提交。提交和推送需要用户另行提出请求。
